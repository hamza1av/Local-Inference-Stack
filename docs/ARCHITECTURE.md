# Architecture & contracts

Target host: **MacBook M1 Pro, 16 GB**. Everything that does ML runs natively on the host
(Metal); containers (OrbStack) only run plain services. Every component can be switched on
and off on its own.

```
             tailnet users ──https──> tailscale serve ──> Open WebUI :3000 (container)
                                                               │  OpenAI API
 agents / scripts / Claude Code / opencode ──────────────────► │
                                                               ▼
                                              gateway :8088  (Rust, host, launchd)
              ┌──────────────┬──────────────┬─────────────┼──────────────┬──────────────┐
              ▼              ▼              ▼             ▼              ▼              ▼
     uzu chat :8000   uzu task :8001  uzu decide :8002  ollama :11434  agents :8092   SQLite
     Qwen3.5 9B       small model     d3-flash (opt.)   embeddinggemma LangGraph      stack.db
                                                                          │  tools
                                       rag MCP :8091 ◄───────────────────┤
                                       kg  MCP :8090 ◄───────────────────┘──► FalkorDB :6390
         every service ──OTLP──► recorder :4320 ──► spool/*.jsonl ──► (on demand) Langfuse :3020
```

## Ports (all bound to 127.0.0.1 unless noted)

| Port | What | Runs as |
|---|---|---|
| 3000 | Open WebUI (published on tailnet via `tailscale serve`) | container `stack-core` |
| 8000 | uzu chat model (`STACK_CHAT_MODEL`) | launchd `local.stack.uzu-chat` |
| 8001 | uzu task model (`STACK_TASK_MODEL`) | launchd `local.stack.uzu-task` |
| 8002 | uzu decision model (`STACK_DECIDE_MODEL`), **on demand** | launchd `local.stack.uzu-decide` |
| 11434 | Ollama (embeddings only) | Ollama.app / `brew services` |
| 8088 | **gateway** – the only OpenAI endpoint clients use (`GATEWAY_BIND`) | launchd `local.stack.gateway` |
| 8090 | kg MCP server (streamable HTTP, path `/mcp`) | launchd `local.stack.kg-mcp` |
| 8091 | rag MCP server (streamable HTTP, path `/mcp`) | launchd `local.stack.rag-mcp` |
| 8092 | agents server (OpenAI-compatible, model `agent`) | launchd `local.stack.agents` |
| 6390 / 3011 | FalkorDB (redis protocol) / FalkorDB browser | container `stack-kg` |
| 4320 / 4321 | trace recorder (OTLP/HTTP, any path) / its health check `/health` | container `stack-obs` |
| 3020 / 3021 | Langfuse UI/API / MinIO S3 API for media, **on demand** | container `stack-langfuse` |
| 8099 | demo MCP server (`agents/examples/my_mcp_server.py`), only while you run it | foreground |

Ports differ from the defaults on purpose so the stack can run next to other local setups.

## Environment

Single source: `.env` at the repo root (generated by `just env` from `.env.example`).
`scripts/env-run.sh` exports it (variables already set in the caller's environment win) and
every just recipe and launchd service runs through it. Compose files are interpolated from those
exported variables and pass each container only what it needs (no `env_file`), so gateway keys
never end up inside containers. The gateway also loads `.env` itself.

## Data

`STACK_DATA` (default `~/.local/share/inference-stack`):

```
stack.db            SQLite (WAL) – shared, tables prefixed by owner
spool/              recorded traces (traces*.jsonl), read by the Langfuse replayer
rag/inbox/          drop documents here for RAG ingestion
kg/vault/           default markdown folder for the knowledge graph (override KG_VAULT)
logs/               launchd stdout/stderr per service
```

### SQLite ownership (`stack.db`, `PRAGMA journal_mode=WAL`, `busy_timeout=5000`)

| Prefix | Owner | Content |
|---|---|---|
| `gw_` | gateway | `gw_requests` – one row per request (ts, user, model, backend, status, latency, tokens) |
| `rag_` | rag | `rag_documents`, `rag_chunks`, `rag_fts` (FTS5), `rag_meta` (embedding model/dim), `rag_vec` (sqlite-vec `vec0`) |
| `agent_` | agents | `agent_notes` (notes tool), `agent_runs` (one row per agent turn) |
| `kg_` | kg | `kg_files` (content hashes), `kg_runs` |

LangGraph checkpoints live in a separate file, `$STACK_DATA/agents.db` (their table names
can't be prefixed).

Each owner creates its own tables idempotently on start. Nobody writes another owner's tables.
Readers that do not load sqlite-vec must not touch `rag_vec`.

## Tracing

All components send OTLP/HTTP traces to `STACK_OTLP_ENDPOINT`
(`http://127.0.0.1:4320/api/public/otel`, the Langfuse path), with header
`x-langfuse-public-key: pk-lf-<component>`. The recorder is always on (~31 MB) and only
appends to `spool/`. Langfuse itself is started on demand (`just obs::langfuse`, ~1.8 GB
while running), the replayer loads the spool and tags each trace `app:<component>`.

## Gateway headers

| Header | Direction | Meaning |
|---|---|---|
| `Authorization: Bearer <key>` | client → gateway | key from `GATEWAY_KEYS`; never forwarded |
| `x-stack-priority: interactive\|background` | client → gateway | queue class (interactive first) |
| `traceparent` / `tracestate` | both | the gateway span becomes a child; forwarded downstream |
| `x-thread-id`, `x-openwebui-*` | client → backend | conversation identity for the agents server |
| `x-request-id`, `x-stack-client` | gateway → backend / client | request id (also in `gw_requests`) and client name |

## launchd services

`scripts/launchd.sh install <name> -- <command…>` writes `~/Library/LaunchAgents/local.stack.<name>.plist`
(KeepAlive, RunAtLoad, logs to `$STACK_DATA/logs/<name>.log`, env from `.env`).
`scripts/launchd.sh uninstall <name>`, `scripts/launchd.sh list`.

## just

Root `justfile` loads every component's `<component>/mod.just` as an optional module
(`just gateway::build`, `just kg::up`, …). Each component's module provides at least
`install`, `uninstall`, `status`.

## Python

Three standalone uv projects, each with its own committed `uv.lock` and `.venv`: `kg/`, `rag/`,
`agents/` (packages `stack-kg`, `stack-rag`, `stack-agents`; import names `stack_kg`,
`stack_rag`, `stack_agents`). They talk to each other only over HTTP (gateway, MCP), never by
import, so each can be installed or left out on its own. All pin `mcp>=1.26,<2`. launchd runs
`<component>/.venv/bin/<cli>` directly (no `uv run` wrapper process, ~20 MB less each).
